# Backend Learning Log

Java/Spring 백엔드 개발을 공부하며 **내가 이해한 것과 직접 검증한 것**을 구분해서 기록합니다.

이 저장소는 AI 조사 자료를 모아 둔 `backend-engineering-study`와 달리, 학습 중 생긴 질문, 내 언어로 설명한 원리, 실제 문제를 해결한 과정과 확인 근거를 담는 개인 학습 기록입니다. AI는 자료 탐색·교정·문장 정리를 도울 수 있지만, 이해·실행·검증 여부는 실제 근거를 기준으로 씁니다.

## 기록 찾기

| 분류 | 담을 내용 |
| --- | --- |
| `til/` | 이해한 개념, 헷갈린 점, 조건·반례, 다음 검증 |
| `problem-solving/` | 실제 문제, 원인 후보, 선택·수정, 결과·한계 |
| `templates/` | 새 기록을 작성할 때 복사하는 템플릿 |

`til/`과 `problem-solving/`은 첫 글을 확정할 때 생성합니다. `drafts/`는 검토 전 파일용으로 사용하며, 공개 전 내용을 다시 확인합니다.

## 기록 원칙

1. **짧은 이해 기록부터:** 개념을 자기 말로 설명할 수 있으면 5~10분 내 핵심 5항목을 남깁니다. 이를 `이해 중심 기록`이라 부릅니다.
2. **검증은 선택적 확장:** 중요한 주제는 실행 조건·예상·실제·증거·한계까지 추가합니다. 이를 `검증 확장 기록`이라 부릅니다. 모든 글에 실험을 강제하지 않습니다.
3. **'이해'와 '실행'을 구별:** 대화에서 설명한 내용은 `이해 확인`, 테스트·로그로 확인한 것만 `실행 검증`으로 표시합니다. 미실행 예제는 미실행이라고 씁니다.
4. **기존 학습 상태와 분리:** 이 저장소의 기록 유형은 기존 Notion/퇴근길 학습의 `L1~L4`, `NEW/EXPOSED/VERIFIED` 상태와 **다른 개념**입니다. 점수나 상태를 임의로 바꾸지 않습니다.
5. **개인 기여를 명확히:** 내가 실제 선택·구현·검증한 범위만 주장합니다. AI가 대신 쓴 설명과 프로젝트에서 검증한 결과를 혼동하지 않습니다.
6. **안전한 공개:** 팀 코드·ERD·API·비공개 수업 자료·계정/인증 정보 등은 승인 없이 공개하지 않습니다. 일반화한 예시라도 검토합니다.
7. **의미 있는 변경만:** 잔디를 채우기 위한 빈 커밋, 무의미한 파일 분할, 사실과 다른 경험은 기록하지 않습니다.

## 작성 방법

- 개념을 기록할 때는 [`templates/til.md`](templates/til.md)를 복사합니다.
- 실제 문제 해결이라면 [`templates/problem-solving.md`](templates/problem-solving.md)를 사용합니다.
- 검증 전 초안은 `drafts/`에 두고, 검토 후 적절한 위치로 옮깁니다.
- 기존 문서와 겹친다면 먼저 **무엇을 새롭게 이해/검증했는지** 확인하고 변경점만 정리합니다.
- GitHub에 게시할 때는 본인이 변경 내용을 최종 검토합니다. 실제 프로필 기여 귀속은 작성자와 브랜치 등 GitHub의 조건을 확인합니다.

> 주 2회 학습 주제 검토는 **커밋 할당량이 아닙니다**. SCENE CREW 작업과 기존 학습을 우선하며, 새 근거가 없는 주는 복습하거나 기록을 보류합니다.
